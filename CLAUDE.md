# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PreStreamer: an Electron + TypeScript presenter and YouTube streamer for church services (macOS, Windows and Linux). Own clean-room app. Songs follow Quelea's workflow, the look follows ProPresenter. Developed and run on macOS; Windows and Linux builds exist but have not been run.

## Commands

```bash
npm start                      # build, rename the dev Electron bundle to "PreStreamer" (macOS), launch
npm run build                  # esbuild -> dist/ (must be re-run before any e2e script)
npm run typecheck              # tsc --noEmit (there is no linter)
npm test                       # vitest, pure logic only
npx vitest run tests/screens.test.ts          # one test file
npx vitest run -t "mirror screens"            # one test by name
npm run test:coverage
node scripts/e2e-stage.mjs     # one end-to-end script (needs a display, ffmpeg on PATH); `npm run e2e` runs all after a build
npm run screenshots            # retake docs/screenshots (launches the app once per picture; windows open briefly)
npm run package:dir            # unpacked installer for a quick check; `npm run package` for installers
npm version patch && git push --follow-tags   # release: the pushed vX.Y.Z tag runs .github/workflows/release.yml (mac arm64 + Intel, Windows, Linux x64: .deb and .AppImage)
```

Node 22+. Development needs `ffmpeg`/`ffprobe` on PATH (`FFMPEG_PATH`/`FFPROBE_PATH` override; installers bundle their own, see `src/main/tools.ts`). macOS has no `timeout` command.

## Architecture

**Processes.** `src/main` (Electron main), `src/preload` (contextBridge, sandboxed), `src/renderer` (pages), `src/shared` (pure logic and types, importable by both). `build.mjs` bundles each entry with esbuild; renderer pages are IIFE bundles and their HTML is copied to `dist/renderer`. A new renderer page or preload therefore needs an entry in `build.mjs` plus a `cpSync` for the HTML.

**Windows.** One operator window (`operator.ts`: tabs Present/Songs/Bible/Mixer/Settings) plus, per screen, an output window (`output.ts`). Virtual screens are offscreen windows whose `paint` frames go to the streamer. Hidden windows do the heavy lifting: the audio engine (`renderer/audio.ts`, Web Audio), PDF pages (`pdf-render.ts`, pdf.js) and `.pptx` slides (`pptx-render.ts`, pptx-preview + `capturePage`). Hidden helper windows get their own preload with a tiny bridge.

**IPC.** Channel names live in the `IPC` const in `shared/types.ts`; each needs a handler in `main/index.ts` and a method in `preload/index.ts` (the `PrestreamerApi` type is derived from it). Main pushes state to renderers (`stateChanged`, `outputUpdate`, `announceState`, ...).

**Screens (`main/screens.ts`, `ScreenManager`).** Owns `ScreenConfig[]` (persisted in `screens.json`), the live windows, the current slide, `next` slide, announcement, `streamLive` and `cameraOnly`. `payloadFor(id)` builds what an output renders (a screen cleared on its own, `blank` / `setBlank`, gets no slide until the next `showSlide`; `isBlank` in `shared/screens.ts` also covers mirrors); a screen with `mirrorOf` gets the followed screen's look/size (and `videoAudio` forced off). What a display screen shows is a role (`roleOf` / `rolePatch` in `shared/screens.ts`: own slides, stage monitor = `STAGE_LOOK`, or mirror); `renderer/screen-form.ts` is the one dialog for adding and editing a screen (the type, display or virtual, is chosen at creation only), `clampSize` keeps sizes within limits and even. `update()` merges `look` patches field by field, so stale copies in the UI cannot overwrite other settings.

**Layout.** Resizable side panels use `renderer/splitter.ts` (`makeSplitter`: a drag handle that sets a CSS variable such as `--pl` on the grid's element and remembers it in localStorage); the grids in `operator.html` have a 6 px column for each handle.

**Slides.** `Slide` (`shared/types.ts`) is text plus optionally `background` (css/image/video), `video` (cue) or `picture` (presentation/picture slide, shown whole above the camera). `SlideView` (`renderer/slideview.ts`) draws everything and is shared by output windows, thumbnails and previews. Layer order, bottom to top: backdrop, live source, video cue, picture, text, stage extras, LIVE badge, announcement. Background precedence: slide's own picture/video, then `look.backgroundMedia`, then css. Camera-only hides backdrop/video/picture/text/announcement. `sameSlide` in `operator.ts` identifies the live slide (label + text + itemId + picture file), so slide labels must stay unique per item. The run sheet's items are song, video, scripture and presentation (pictures reuse `presentation`).

**Streaming.** Where it goes (`mode`: YouTube or a file) and which virtual screen is in `StreamSettings` (`shared/stream-settings.ts`, edited on the Settings → Stream page, `renderer/stream-settings.ts`, the only place for them (the Present tab's Stream section has no link to it); the key is saved through `IPC.streamKeySet`); the Present tab's Stream panel only summarises that and starts it, always with the mixer's port as sound. `main/streamer.ts` pipes raw BGRA frames of the virtual screen to an ffmpeg child process on a paced loop; audio arrives over a loopback TCP socket from `AudioBridge` (`main/audio.ts`), which feeds silence when the mixer is off so the stream never stalls. `-probesize 32 -analyzeduration 0` is essential for start-up. Stats come from `-progress pipe:1` (`shared/stream-stats.ts`). Encoder args come from `shared/stream-settings.ts` plus a hardware-encoder probe (only VideoToolbox verified).

**Mixer.** `shared/mixer.ts` is the model (strips keyed by `stripKey` = device + channel; order in the array is display order only). Every strip and the master has a **chain**: an ordered `Effect[]` (`{id, type}` + the settings of hpf, eq, gate, comp, limiter, deesser, reverb or delay), between the strip's trim and fader (master: `sum` and master fader). Effect ids are stable and unique across the mixer (sanitize keeps them; the engine tells chains apart by id, the meters report gain reduction by id, `MASTER`'s default limiter has the fixed id `master-limiter`); `sanitizeMixer` also converts old files (fixed hpf/eq/gate/comp/limiter fields, `masterLimiter`) into chains. `renderer/effects.ts` makes the nodes of one effect (`Fx`), `renderer/audio.ts` wires a chain with `syncChain` (rewires only when the id order changes; a bypassed effect stays in the graph and passes the signal on, so toggling never clicks) and applies changes live; worklets: `gate`, `compressor` (also the limiter), `deesser` (all channel-count agnostic, linked detection, report gain reduction on their port). The reverb's impulse response is made in `shared/reverb.ts`, not a file. The master's sync delay is an ordinary effect (`syncdelay`, a `DelayNode`; the default master chain is a limiter and a sync delay at 0 ms, and old files' `delayMs` becomes one on load). The Audience panel in the Mixer tab (the Stream panel holds the channel strips, then the master strip with the monitor controls beside it; the Audience panel is separate) edits settings of the screen that plays video sound (`Look.videoAudio / audioOutput / videoVolumeDb / videoMuted`, applied by `SlideView.applyLevel` in that screen's window, so the sound stays in step with the picture) and shows its meter, taken from the audio window's `app:video` source, which is therefore always open while the engine runs (`Meters.audience`). The monitor (`MixerConfig.monitor`, `syncMonitor` in `audio.ts`) is a copy of the stream mix, after the master chain, into a `MediaStreamAudioDestinationNode`, played by an `Audio` element whose `setSinkId` picks the output device: the AudioContext's own destination stays silent, and video sound for the room is a different path (the screen window's `audioOutput`). The Mixer tab (`renderer/mixer.ts` draws the chain as cards joined by arrows; `knob.ts`, `mixer-graphs.ts`, curve maths in `shared/curves.ts`) edits it and `main` persists `mixer.json`. Undo/redo is `shared/history.ts` (`History` over JSON snapshots) driven by `mixer.ts`: `commit()` marks a change, and half a second without another one settles it into the history; Cmd/Ctrl+Z is a document keydown listener active on the Mixer tab only (text boxes keep their own undo). A new effect type needs: the config + `RANGES` + `defaultEffect` + `effectParams` in `shared/mixer.ts`, its nodes in `effects.ts`, its card in `effectBody` in `mixer.ts`, and a line in `EFFECT_INFO`. The built-in `app:video` source carries the sound of video cues. The mixer starts by itself when the app opens.

**ATEM.** `shared/atem.ts` is the model (status, commands, address validation, `switchableInputs`); `main/atem.ts` (`AtemController`) keeps the link through `atem-connection` (UDP, Ethernet only; the Mini's USB is a webcam), retries every 8 s, and takes the client through a factory so tests use a fake. Status goes to the operator over `IPC.atemState`; `renderer/atem-panel.ts` shows it in the Present tab (under the screens) and the Monitor tab, and hides its whole section (`host`) while `state !== 'connected'`; the address and `AtemButtons` (show Preview / Cut / Auto, in `atem.json`, carried by `AtemStatus.buttons`) are edited in Settings → ATEM. Stream health is likewise hidden unless a stream or recording is running. The library is loaded lazily, runs with `disableMultithreaded` (its worker process cannot start from an asar) and is an esbuild `external`. The address is saved in `atem.json`; with `PRESTREAMER_USER_DATA` set the search is off unless `PRESTREAMER_ATEM=1`.

**NDI.** A screen of kind `ndi` (`ScreenKind`) is drawn offscreen like a virtual one but takes display roles (`hasRoles`/`isOffscreen` in `shared/screens.ts`; only `virtual` is the stream's screen: camera-only, the stream picker and the LIVE state stay with it). While it is live, `main/ndi.ts` (`NdiOutputs`) runs one `dist/native/ndisend` per screen (`src/native/ndisend.c`, compiled by `build.mjs` with `cc` on macOS/Linux, not Windows yet): raw BGRA frames on stdin at 30 fps (`NDI_FPS`; the last frame is repeated, a frame is skipped when the pipe is full), stderr says `READY` or `ERROR ...`. Sound (`ScreenConfig.ndiSound`: `'stream'` by default, `'video'` or `'none'`): unless `'none'` the helper is started with `audio` and takes interleaved stereo f32 at 48 kHz on fd 3, fed by `NdiOutputs.audio(which, pcm)`: `'stream'` is the mixer's mix (`AudioBridge.onPcm`, the blocks the stream gets, whether or not a stream runs), `'video'` is the video cues' own sound (a second `pcm-tap` on the always-open `app:video` source in `renderer/audio.ts`, sent over `AUDIO_IPC.videoPcm` to `AudioBridge.onVideoPcm`; before the strips and master, silence while no video plays). Blocks are dropped when an output is behind, nothing is delayed to match the picture; changing the name or sound restarts the output. The helper `dlopen`s NDI's library, so nothing of NDI is linked; where to find it is `ndiLibraryCandidates` in `shared/ndi.ts` (`PRESTREAMER_NDI_LIB`, `resources/ndi` from `vendor/ndi/<os>-<arch>` via `extraResources`, then installed NDI Tools/Runtime). `ndisend receive` is a test-only mode that finds a source and prints the centre pixel and the audio it got (level, pitch, longest gap) (`scripts/e2e-ndi.mjs`, which skips without a library). The status per screen travels in `ScreenState.ndi`. Not verified: real NDI decoders/hardware, Windows, Linux.

**Languages.** The interface is English and Slovak (`Lang`, `LANGUAGES` in `shared/i18n/index.ts`). Every user-visible text is `t('namespace.key', {params})`; the messages live in `shared/i18n/messages/<namespace>.ts` (`operator`, `songs`, `bible`, `settings`, `stream`, `mixer`, `devices`, `main`, `shared`) as `defineMessages({en…}, {sk…})`: the compiler requires the Slovak object to have exactly the English keys, every key must start with its file's name (tested), and a unit test compares placeholders (`{name}`) of both languages. Plural messages are `{one, few, many, other}` objects chosen by a parameter `n` (Slovak has one/few/other). English text is what the e2e scripts and unit tests match on, so change it only together with them; code must never compare against translated text (use ids). Static HTML text uses `data-i18n*` attributes filled by `renderer/i18n-dom.ts` `translateDocument()`. Which language: `language.json` in userData holds `'auto' | 'en' | 'sk'` (Settings → Language, `renderer/language-settings.ts`); `main/language.ts` resolves it (auto = the computer's locale, English when there is no translation) and `main/early-language.ts`, imported first by `main/index.ts`, sets it before other modules build text at load; the preloads (`index.ts`, `audio.ts`) hand it to the window (`prestreamer.language` / `audioBridge.language`, read synchronously over `IPC.languageSync`) and `t()` picks it up from there, so text may be built at module load in a renderer. Changing the language reloads the operator window; open output windows keep theirs until reopened. Text computed when a module loads is a problem in main (use a function or getter, as `ndiMissing()`, `idleAudio.message`). Persisted data is never translated (screen names, song text, quick messages, "Light N" style names are created in the language of the moment). Tests and dev hooks run in English unless `PRESTREAMER_LANG` says otherwise (`PRESTREAMER_USER_DATA` implies English). Adding a language: add it to `LANGUAGES`, a column to `defineMessages` (define.ts) and fill it everywhere (the compiler lists what is missing), plus a Slovak-style page set in `docs/<lang>/` and `node scripts/screenshots.mjs --lang=<lang>` for the pictures in `docs/screenshots/<lang>/`. Not translated: the OS application menu, errors of the hidden PDF/PPTX renderers, the user guide's English-only developer notes.

**DMX.** `shared/dmx.ts` is the model: `DmxSettings` (`dmx.json`: `enabled`, `port`, `fadeSec`, `blackoutOnQuit`, `startScene`, `fixtures` = name/kind/address/channels, `scenes` = per-fixture channel levels + own fade), `renderUniverse` (levels × grand master, dark on blackout), `blendLevels`, patch checks, `dmxPortCandidates` (`/dev/cu.usbserial-*` on macOS, `/dev/ttyUSB*` on Linux). `main/dmx.ts` (`DmxController`) takes the hardware through `DmxDeps` (tests use a fake): nothing is opened or sent until the first command (or a start scene), so starting the app never changes the room; scenes fade on a 25 ms tick, faders/master/blackout are immediate, frames identical to the last are not rewritten, a lost interface is retried every 5 s while something is on. `main/dmx-helper.ts` is the real deps: one `dist/native/dmxsend` child (`src/native/dmxsend.c`, `cc` on macOS/Linux, optional on Linux) that makes the Open DMX USB's signal itself (break via `TIOCSBRK`, 250000 baud 8N2 via `IOSSIOSPEED` / `termios2`) and repeats the newest 512-byte block on stdin at about 30 Hz, `READY`/`ERROR` on stderr; `raw` mode writes the frame (start code + slots) into a file, which `PRESTREAMER_DMX_FAKE=<file>` uses for e2e and screenshots (with `PRESTREAMER_USER_DATA` set and no fake, output is refused). IPC `dmxGet/dmxState/dmxSetSettings/dmxCommand` (`DmxCommand`: scene, level, master, blackout, rescan); `renderer/dmx-panel.ts` (Present tab, hidden while `state === 'off'`, rebuilt only when lights/scenes change so a dragged fader stays) and `renderer/dmx-settings.ts` (Settings → DMX, saved on each change, holds a status push while a field has focus). User guide `docs/dmx.md`. Not built: scenes per run sheet item, chases, several universes, Art-Net/sACN, Windows. Not verified: a real interface and lights (the helper was only run in `raw` mode).

**Multichannel capture.** Chromium opens a USB interface with two channels at most, so `main/native-audio.ts` (`NativeAudio`) reads wider devices with a program per platform from `src/native`, built by `build.mjs` into `dist/native` (unpacked from the asar): macOS `avcapture.swift` (CoreAudio; ffmpeg's avfoundation input drops about one buffer in nine and must not be used), Linux `alsacapture.c` (ALSA, `dlopen`s libasound so no headers are needed; device `hw:CARD=<id>`), Windows `wasapicapture.c` (WASAPI shared mode at the device's own format, `list` and `capture` modes). All write interleaved f32le at 48 kHz to stdout and print an ffmpeg-style `Stream #0:0: Audio: ... N channels` line on stderr when started (`parseFfmpegAudio`); `FrameSplitter` aligns the bytes and the `native-in` worklet buffers them. The device lists come from `system_profiler` (macOS), `/proc/asound` (Linux, `parseAlsaInputs`) and `wasapicapture list` (Windows, `parseWasapiList`). The test rig (`PRESTREAMER_NATIVE_TEST=1`) still uses ffmpeg on every platform. Only macOS was run against real hardware; Linux/Windows are compile-checked only.

**Songs and Quelea.** `Song` mirrors Quelea's song so a later import is lossless: a Quelea `<section title=… >` (+ optional `<theme>`, a `$`-separated `key:value` string with `backgroundcolour`/`backgroundimage`/`backgroundvideo`) = one slide (`[title]` + lines), the section's theme background = `slideBackgrounds[i]` (positional, trimmed on Save by `trimSlideBackgrounds`), the song's theme = `background`, and the metadata (`author, copyright, ccli, year, publisher, key, capo, notes`) are optional fields. Visuals live in the song record (saved by the editor's Save, or immediately from the Present tab); service items only reference `songId`. Not mapped yet: `sequence`, translations, `capitalise`, small lines. Quelea's own song XML (`<songs><song><title/><author/><lyrics><section …>`) was read from the format description bundled in Quelea.app (`songformat.xsl`, source in `Resources/src`); never run Quelea. Songs are imported and exported from the Songs tab (`main/song-import.ts`, `shared/quelea.ts`, `shared/song-import.ts`: Quelea's own song files and PDFs of lyrics).

**Appearance.** `shared/appearance.ts` holds the app-wide look (`appearance.json`, pushed over `IPC.appearanceChanged`): a default background for songs, one for scripture, and the logo. `applyDefaultBackground` fills slides that have no picture/video of their own, applied where the operator builds slides (`songSlides`, `readingOf`, Bible `present`), so precedence is slide > song > app default > screen `backgroundMedia` > colour. The logo is an ordinary picture slide (label `Logo`) shown by the header button / `L`. Deleting a library file runs `forgetAppearanceMedia`.

**Media.** Everything imported lives in `userData/media`, served through the `media://` protocol with HTTP range support (`main/library.ts`). `library.json` names the backgrounds library (`main/media-library.ts`); slide pictures of presentations/pictures use generated names so they stay out of it.

**Persistence.** JSON files in `userData` (`prestreamer` folder): songs, services, screens, mixer, stream settings, session (`shared/session.ts`: window bounds, open screens), `bibles/`, `media/`. Session restore never reopens a full-screen output on the main display and never starts a stream.

## User guide

`docs/` is the user guide (English; the Slovak translation is `docs/sk/`, same file names, UI names as the Slovak catalog has them), written by task (service, songs, Bible, media, announcements, screens, streaming, sound, ATEM, NDI, DMX, shortcuts, troubleshooting, a Sunday checklist) with `index.md` as the home page; it is served by GitHub Pages from the `docs/` folder of `main` (`docs/_config.yml`, theme `jekyll-theme-minimal`; every page has front matter and links to its siblings as relative `.md` links so it reads the same on github.com and on the site). Its pictures are `docs/screenshots/*.png`, all taken by `scripts/screenshots.mjs` (the tour pictures put numbered markers over the window with the `mark` helper); when the look of the app changes, retake them and check the numbers in the text still match. Say plainly in the guide which parts are not verified with real equipment (same list as the README's table).

## Testing conventions

- Put logic that does not need Electron in `src/shared` (or the few pure `src/main` modules listed in `vitest.config.mts`) and unit-test it in `tests/`.
- UI and windows are verified by `scripts/e2e-*.mjs`: each launches the real app with env-var **dev hooks** (`src/main/devhooks.ts`, documented at the top of that file: `PRESTREAMER_EVAL`, `_SNAPSHOT`, `_STREAMTEST`, `_NO_AUTO_OPEN`, `_PRESENTATION_FILE`, `_MEDIA_FILE`, ...), runs JS in the operator window and prints PASS/FAIL lines. Native file dialogs are replaced by env vars.
- Always run e2e with `PRESTREAMER_USER_DATA` pointing at a scratch folder (the scripts do, and delete it first); this also disables the Quelea auto-import.
- The snapshot/stream hooks keep windows `alwaysOnTop` because macOS stops painting occluded windows.
- Scripts that execute JS in the page: a line starting with `[` after a statement without `;` is joined to it. Don't dispatch key events on `window` (the handler calls `e.target.matches`), use `document.body`.

## Constraints

- Company policy forbids running Quelea.app; its Bible/song files are only read.
- Never store a YouTube stream key anywhere or stream with one without being told to; tests stream to a local file or a local RTMP server (`PRESTREAMER_RTMP_URL`).
- Don't use `pkill -f` patterns (they can kill the user's running app).
- Commit and push only when asked.
- Platform code lives behind `process.platform` in few places (encoders in `streamer.ts`, Quelea folders in `bibles.ts`, converters in `presentations.ts`, Linux window-system switches and the menu in `main/index.ts`); `package.json` → `build` has `mac`, `win` and `linux` blocks and `npmRebuild: false` (the only native module, atem-connection's freetype2, ships N-API prebuilds for every platform, and cross-platform packaging cannot recompile it).
- Not verified: running the app on Windows or Linux, a real YouTube stream, Behringer Wing/ATEM hardware, Keynote/PowerPoint fallback import on macOS, signed builds. GitHub Actions work (`ci.yml` unit tests, `release.yml` published v0.1.0); the e2e jobs in CI are non-blocking.
